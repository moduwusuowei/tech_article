Debug

根因分析，找到问题的本质

🔧 什么是 Debug

Debug 是一个根因分析技能。与表面修复不同，Debug 会深入分析问题的根本原因，而不是只修表面。

它的核心理念是："不要只问'怎么修'，要问'为什么坏'。"找到根本原因，才能防止同类问题再次发生。

📋 使用场景

  • 反复出现的 Bug："这个 bug 修了又出现"
  • 奇怪的行为："代码逻辑看起来对，但结果不对"
  • 性能问题："系统突然变慢，找不到原因"
  • 并发问题："偶尔崩溃，可能是竞态条件"
  • 生产问题排查："线上出了问题，需要快速定位"
🌰 场景示例：修复内存泄漏

问题："应用运行几天后内存持续增长"

表面修复："加个定时重启"（不解决根本问题）

Debug 根因分析：

1. 分析内存dump，发现对象持续增长

2. 追踪引用链，发现 EventEmitter 监听器未移除

3. 找到根因：组件卸载时未清理事件监听

4. 修复：componentWillUnmount 中清理监听器

结果：从根本上解决了内存泄漏

⌨️ 命令格式

基础命令：

debug "修复登录超时问题"

指定分析范围：

debug --scope "api/*" "分析接口性能问题"

带上下文：

debug --error "TypeError: Cannot read property" "分析报错"

🔍 分析方法

Debug 采用结构化分析方法：

  • 现象收集：收集所有相关的错误信息
  • 假设生成：提出可能的根因假设
  • 假设验证：用证据验证或推翻假设
  • 根因确认：找到真正的根本原因
  • 修复建议：提出根本性解决方案
💡 5 Why 分析法

Debug 常用"5 Why"：连续问 5 次"为什么"，层层深入找到根本原因。

⚠️ 注意事项

  • 需要复现环境：最好能在测试环境复现问题
  • 可能需要日志：日志对定位问题很重要
  • 不是万能：有些问题难以在短期内定位
  • 复杂问题耗时：根因分析可能需要较长时间
