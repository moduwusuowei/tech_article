Autopilot

从想法到交付的全自动流水线

🚀 什么是 Autopilot

Autopilot 是最强大的执行技能。它是一个端到端的自动化流水线，从接收一个模糊的想法开始，自动完成规划、开发、测试、验证，最终交付可用的产品。

你只需要说"Build me a REST API for user management"，Autopilot 会自动完成从设计到部署的全部工作。

📋 使用场景

  • 从零构建项目："autopilot 创建一个博客系统"
  • 快速原型开发：需要快速验证想法的可行性
  • 完整功能交付：需要端到端交付，不只是代码
  • 学习参考：通过 Autopilot 生成的结构学习新技术
🌰 场景示例：快速构建 MVP

用户说："autopilot 创建一个任务管理应用"

Autopilot 自动执行：

1. 分析需求，确定技术栈

2. 创建项目结构

3. 实现核心功能

4. 编写测试

5. 生成文档

6. 验证交付物

用户得到一个完整的、可运行的应用

⌨️ 命令格式

基础命令：

autopilot "构建用户认证系统"

指定技术栈：

autopilot "创建一个博客，使用 Next.js + Prisma"

带约束条件：

autopilot "API 要支持 REST，要用 TypeScript"

⚙️ 工作原理

Autopilot 采用自动化流水线：

  • Expansion：扩展需求，明确范围
  • Planning：制定实现计划
  • Execution：执行开发
  • QA：质量检查
  • Validation：验证交付物
  • Complete：完成交付
💡 与其他技能的区别

Plan 只规划不编码 | Ralph 执行单任务 | Team 并行执行子任务 | Autopilot 是完整的端到端流水线

📦 交付物检查清单

Autopilot 完成时会交付：

  • 完整代码：可运行的项目代码
  • 依赖配置：package.json / requirements.txt 等
  • 运行说明：README 或文档
  • 测试代码：基础测试覆盖
  • 类型定义：TypeScript / 类型提示

⚠️ 注意事项

  • 消耗较大：端到端流水线消耗较多 token
  • 复杂任务首选：简单任务用 ralph 更经济
  • 需要人工确认：关键决策点会暂停等待确认
  • 不是银弹：高度创新的设计仍需要人工介入
⚠️ 不要用 Autopilot 的场景

只需要修改一行代码 | 只需要解释一个概念 | 预算有限想精打细算
