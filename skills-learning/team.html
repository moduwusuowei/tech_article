Team

多 Agent 协调并行执行，效率倍增

👥 什么是 Team

Team 是一个多 Agent 协同执行技能。它会启动多个专业化的 agent，分别负责不同的任务，协同工作完成复杂项目。

就像一个公司有不同部门一样：产品经理规划、工程师开发、测试人员验证。Team 让这些角色同时工作。

📋 使用场景

  • 大型项目开发：前后端同时开发，多模块并行推进
  • 代码审查：多个视角同时审查（安全、性能、风格）
  • 需求分析：产品、技术，用户多角度分析
  • 系统设计：架构师、数据库专家、运维专家同时参与
  • 完整功能交付：规划→开发→测试→文档一条龙
🌰 场景示例：开发电商系统

用户说："team 开发电商后端 API"

Team 自动分配角色：

• Planner Agent：分析需求，拆分任务

• Backend Agent：实现 API 接口

• Database Agent：设计数据模型

• Test Agent：编写测试用例

• Review Agent：代码审查

各 agent 并行工作，结果汇总

⌨️ 命令格式

基础命令：

team "开发用户模块"

带团队配置：

team --agents planner,executor,test-engineer "重构订单服务"

指定计划文件：

team ".omc/plans/prd-xxx.md"

⚙️ 工作原理

Team 采用分阶段流水线：

  • team-plan：任务分解和规划
  • team-prd：需求澄清和验收标准
  • team-exec：并行执行各个子任务
  • team-verify：验证执行结果
  • team-fix：修复问题（可选循环）
💡 并行度控制

默认最多 6 个并行 agent。支持独立任务并行执行，有依赖关系的任务按顺序执行。

📊 团队组成

常见的团队配置：

功能开发团队

analyst → planner → executor → test-engineer → code-reviewer → verifier

Bug 调查团队

explore + debugger + executor + test-engineer + verifier

代码审查团队

style-reviewer + code-reviewer + api-reviewer + security-reviewer

⚠️ 注意事项

  • 任务需要可拆分：Team 适合可以分解为独立子任务的项目
  • 上下文共享：通过状态文件共享进度和数据
  • 开销较大：多 agent 消耗更多 token，适合复杂任务
  • 优先级选择：推荐通过 Plan 先规划，再由 Team 执行
⚠️ 不要用 Team 的场景

单个简单任务（用 ralph 或直接执行即可）| 需要共享大量上下文的紧密耦合任务
