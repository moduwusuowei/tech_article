Self-improve

自主进化改进代码 · 持续优化代码质量和结构

🧬 什么是 Self-improve？

Self-improve 是一种自主进化的工作模式，通过评估-反馈循环持续改进代码质量。它不满足于"能用就行"，而是追求代码的结构、可读性、可维护性不断进化。

🌰 工作流程

1. 执行任务 → 产生初始代码

2. 评估质量 → 发现问题（冗余、耦合、风格不一致...）

3. 反馈改进 → 重构/优化代码

4. 再次评估 → 验证改进效果

5. 循环直到达成质量目标

🎯 触发条件

以下情况适合使用 Self-improve：

  • 代码存在明显的结构问题，需要重构
  • 多个文件代码风格不一致，需要统一
  • 发现重复代码模式，需要抽象
  • 代码复杂度超标，需要简化
  • 用户要求"优化这段代码"或"改善代码质量"
💡 注意

Self-improve 适用于代码质量改进，不适合紧急 bug 修复。如果是 bug 修复，使用 Debug skill 更合适。

📊 评估维度

Self-improve 从多个维度评估代码质量：

/**
 * 代码质量评估维度
 */
const QUALITY_DIMENSIONS = {
  // 结构层面
  structure: {
    '模块化程度': '是否按职责分离',
    '依赖关系': '循环依赖、过度耦合',
    '层次清晰度': '架构层次是否合理'
  },

  // 可读性
  readability: {
    '命名规范': '变量/函数命名是否清晰',
    '注释质量': '是否有必要的注释',
    '函数长度': '函数是否过长需要拆分'
  },

  // 可维护性
  maintainability: {
    '重复代码': '是否有重复逻辑可提取',
    '硬编码': '是否有魔法值需要抽取',
    '错误处理': '异常情况是否处理'
  },

  // 性能（可选）
  performance: {
    '算法复杂度': '是否使用了低效算法',
    '资源使用': '是否有资源泄漏风险'
  }
};

💻 执行示例

用户说："优化这个用户模块的代码"

// 1. 初始评估
评估 UserModule 的代码质量：
- 函数 userLogin 过长（120行）
- userCreate 和 userUpdate 有重复的字段校验逻辑
- 用户密码直接存储在内存中
- 多处硬编码的错误码

// 2. 改进计划
优先级排序：
1. [高] 密码加密存储 - 安全问题
2. [高] 提取重复校验逻辑 - DRY 原则
3. [中] 拆分 userLogin 函数 - 可读性
4. [低] 抽取错误码配置 - 可维护性

// 3. 逐步执行
Step 1: 添加密码加密
Step 2: 提取 validateUserFields() 函数
Step 3: 拆分 userLogin 为多个子函数
Step 4: 创建 errorCodes.js 配置文件

// 4. 验证改进
改进后：
- 密码使用 bcrypt 加密存储 ✓
- 字段校验复用率提升 60% ✓
- userLogin 拆分为 5 个子函数 ✓
- 错误码统一管理 ✓

🔁 进化循环

Self-improve 的核心是一个持续改进的循环：

📝
评估
→
🎯
定位问题
→
🔧
改进
→
✅
验证
→
🔄
继续循环

每次循环后，代码质量都会提升一个台阶。这个过程可以重复进行，直到达到预期的质量标准。

🏆 最佳实践

  • 小步快跑：每次改进聚焦一个问题，避免大规模重写
  • 可验证：每次改进后运行测试，确保功能不受影响
  • 有记录：在 commit 中记录改进的原因和效果
  • 有边界：设定质量底线，达到后停止进化避免过度设计
  • 分优先级：安全问题 > 功能问题 > 风格问题
